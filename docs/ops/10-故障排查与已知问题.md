## B. 典型故障处置

### B1. 服务器起不来 / 世界创建失败

1. 看 `/logs/latest.log` 尾部 `ERROR` / `Exception`。
2. 常见根因链：数据包 zip 缺 `pack.mcmeta` → `Missing metadata` → `WORLD_CREATOR_FAILED`。
3. 处置：
   - 修包（确保 `pack.mcmeta` 在 zip **根**）；
   - 或临时移走坏包：SFTP 把 `world/datapacks/x.zip` 改名 `x.zip.bad`；
   - 重启；
   - 日志确认无 `Missing metadata`、目标世界 `ServerLevel[...]` 出现。

### B2. Hikari 连接风暴（CoreProtect / Slimefun）

**症状**：日志刷 `HikariPool-1 - Connection is not available` / `Communication link failure`。

**根因**：远程 MySQL（`160.202.254.65`）瞬断或被限流，插件疯狂重连。

**处置**：
1. 确认是哪家插件（日志有插件名）；
2. 拉长其连接池：`connectionTimeout`、`maxLifetime`、`keepaliveTime`（参考 Slimefun 2026-10-10 改法）；
3. 若持续，考虑临时禁用该插件的数据功能（CoreProtect 可暂停记录，查不了历史但保服）；
4. 联系主机/DBA 查 MySQL 侧。

### B3. 掉落物/「was killed」刷屏

**症状**：大量 `Entity … was killed`、`Dropped …` 日志，实体堆积掉 TPS。

**根因**：废土刷怪清理函数 `/kill` 按 generic 死亡掉落（2026-10-10 已修，加了 `DeathLootTable=empty`）。

**若复发**：
1. 确认数据包是否还是修好的版本（md5/文件数）；
2. 看是哪个函数在杀（日志坐标对回 mcfunction）；
3. `/kill` 前确保 `DeathLootTable` 已置空；
4. 紧急：`/kill @e[type=item]` 清场（OP）。

### B4. 玩家背包「丢东西」

**不要直接赔**。按序排查：

1. 确认玩家当前所在世界 → MV JSON 是分世界的；
2. 去 `plugins/Multiverse-Inventories/worlds/` 看其他世界 JSON 里是否有那些物品；
3. 看 InvAutoBackup `backups/<uuid>/` 最近快照；
4. 游戏内 `/co i` / `/co l container` 查容器流水；
5. 都没有再考虑补偿，补偿用 `/give` 或从快照手动贴 JSON。

**常见误会**：进废土世界时主世界背包「消失」——实为正常隔离，废土坏了没切换过去而已（见 B1/已知问题 #1）。

### B5. 基岩版玩家进不来 / 掉线

1. Geyser/Floodgate 日志；
2. 确认 `BedrockPlayerSupport` 与 Geyser 版本匹配当前 MC；
3. 大版本更新后 **先别让 geyserupdater 自动升**，手动确认兼容。

### B6. TPS 低 / 卡顿

1. spark 采样（`/spark profiler start` … 或服务端 spark 命令）；
2. 看 `logs/gc.log` 有没有长停顿（>500ms）；
3. 常见点：漏斗海、实体堆、区块加载风暴、异步线程争用；
4. 应急：`/kill @e[type=item]`、降 view-distance（改 server.properties）、重启；
5. 长期：对照 [09-性能优化记录](09-性能优化记录.md) 逐层查。

### B7. 插件报错但服还能跑

1. 日志定位插件名与异常栈；
2. 查该插件是否依赖另一插件（Vault、PlaceholderAPI、ProtocolLib…）；
3. 试 `plugins/Xxx.jar` → `Xxx.jar.disabled` + 重启（禁用）；
4. 无玩家在线时禁用，避免登录时序问题。

## C. 日志检索速查

```bash
# 最近错误
grep -E "ERROR|Exception" logs/latest.log | tail -50

# 某玩家相关
grep "YonmkoQWQ" logs/latest.log | tail -50

# 世界创建
grep -E "Missing metadata|WORLD_CREATOR|ServerLevel" logs/latest.log

# 掉落物风暴
grep -c "was killed" logs/latest.log

# GC 长停顿（需人类可读转换，或直接看 gc.log 时间戳间隔）
grep "Pause" logs/gc.log | tail
```

本机 SFTP 工具：`cd srv && node gf.mjs`（内置 grep 逻辑），或 `getbin` 拉下来本地搜。

## D. 应急手册（一页纸）

| 场景 | 动作 |
|---|---|
| 服起不来 | latest.log 尾部 → 坏包移走 → 重启 → 修包传回 |
| 掉落物刷屏 | `/kill @e[type=item]` → 查废土函数 DeathLootTable |
| Hikari 风暴 | 拉长超时 → 持续则禁该插件数据功能 |
| 玩家丢物品 | 查其他世界 MV JSON → InvAutoBackup → `/co i` |
| TPS 低 | spark → GC 日志 → 降视距/清实体 → 重启 |
| 需要执行命令 | 无 RCON：面板 or 游戏内 OP |
