# 11 · 运维操作规程

标准流程集。每条都是「前置检查 → 执行 → 验证 → 收尾」。**改完服务器，记得更新 [03-更新日志](03-更新日志.md)。**

---

## 0. 通用原则

1. **动文件前先 `getbin` 拉一份本地留底**，改坏了能传回。
2. **上传用 `up.mjs`**，它回读 md5 校验；手动 scp 不校验容易传半截。
3. **需要重启的操作**，确认当前无玩家重要操作（战斗/下界门/正在放置贵重方块）；公告「即将重启」。
4. **玩家在线时不要改其背包 JSON**——会被会话保存覆盖。
5. **凭据不进 git、不进文档正文**；只在 `srv/conn.mjs`、插件 config 等既有处。

## 1. 改配置（config.yml / server.properties）

**适用**：性能键、开关、max-players、motd 等。

```
前置：
  - 确认键名在 /config.yml 中存在（先 getbin 本地 grep）
  - 留底：cp 本地副本 config.yml.bak-<date>

执行：
  1. getbin /config.yml → 本地
  2. 编辑（YAML 缩进敏感；用 python yaml 或在线校验器过一遍）
  3. up.mjs 本地 → /config.yml → 核 md5
  4. 面板重启

验证：
  - latest.log 启动段无 Invalid/unknown key
  - 必要时 getbin 拉回生成文件（bukkit.yml 等）抽查该键已写入
  - 功能验证（如改 hopper 后看商店、改 EAR 后看农场）

收尾：
  - 更新日志记一条「变更」
```

**server.properties**：直接改该文件（Leaf 不从 config.yml 生成它），同样走「留底→改→传→重启→验证」。

## 2. 换数据包

**适用**：wasteland_zh、ruined_zh2、deeper_dark_zh3、地形包等。

```
前置：
  - 本地包先过三关：
      1) pack.mcmeta 在 zip 根：python3 -c "import zipfile; print('pack.mcmeta' in zipfile.ZipFile('x.zip').namelist())"
      2) unzip -l 文件数与预期一致
      3) 关键 json 能 parse（enchantment 等）
  - 备份旧包：up 前 getbin 旧 zip 到本地 *.bak

执行：
  1. 公告重启
  2. getbin 旧包留底
  3. up.mjs 新包 → /world/datapacks/x.zip
  4. 面板重启

验证：
  - latest.log 无 Missing metadata
  - 相关维度 ServerLevel[...] 出现
  - 游戏内 /datapack list 显示 enabled
  - 功能点抽查（如废土进一趟看变异怪/附魔是否在）

收尾：
  - 更新日志「修复/变更」+ 本地保留新包 md5
```

**回滚**：把 `.bak` 传回 + 重启。

## 3. 重启服务器

```
前置（见 §5 完整 checklist）：
  - 无挂起的配置/数据包半成品
  - 需要改的玩家背包已改完
  - 公告玩家

执行：主机面板 → 重启（或 stop → start）

验证：
  - latest.log：`Done (Xs)`；无 WORLD_CREATOR_FAILED / Missing metadata / 大段 Exception
  - 各维度 ServerLevel 出现
  - 玩家能登录、能进各世界
  - InvAutoBackup 等新插件已加载（日志有其 enable 行）

收尾：
  - 更新日志记重启时间与验证结果
```

---

## 4. 装/换插件

```
前置：
  - 确认与 MC 26.2 / Leaf 的兼容（Paper API 版本、ProtocolLib/packetevents 版本）
  - 留底旧 jar（如替换）

执行：
  1. 公告（可选，小插件不扰民）
  2. up.mjs 传 jar → /plugins/Xxx.jar
  3. 重启（在线 reload 不安全，多数插件不支持）

验证：
  - 启动日志有 enable 行、无 ClassNotFound / NoSuchMethod
  - 主要命令跑一遍

卸载：
  1. 面板 stop（不建议热卸）
  2. jar 改名 .disabled 或移走
  3. 数据目录 plugins/Xxx/ 可留可删（留着保险）
  4. start
```

**已知待处理**：`5be6590).jar`、`v6.1.0.jar`、`aad97af).jar`、`OptPlugin.jar`——先查清是什么再动。

## 5. 重启前 Checklist（复制用）

```
[ ] /config.yml 已上传且 md5 正确（若本轮改过）
[ ] server.properties 已确认（若改过）
[ ] 数据包 zip 内有根级 pack.mcmeta（若换过包）
[ ] 需要改背包的玩家已离线且 JSON 已传完
[ ] 新插件 jar 已到位、旧插件冲突已排除
[ ] 公告已发
[ ] 面板重启

重启后：
[ ] 无 Missing metadata / WORLD_CREATOR_FAILED
[ ] 目标维度 ServerLevel 出现
[ ] InvAutoBackup / 目标插件日志有加载行
[ ] 抽查玩家能登录、能传送
[ ] 更新日志已写
```

## 6. 给玩家补东西 / 改背包

**优先级**：游戏内 OP `/give`（需玩家离线可绕过 MV 覆盖问题吗？——**不行**，在线 `/give` 会进内存并在退服时保存，可用）> InvAutoBackup restore > 手改 MV JSON。

### 6a. 简单补一件（推荐）

玩家在线 → OP 开创造/用命令 `/give <玩家> <物品> <数量> [组件]`。
玩家离线 → 等他上线再给，或离线时手改 JSON。

### 6b. 手改 MV JSON（复杂组件/批量）

```
前置：玩家离线；重新 getbin 拉最新 <世界>/<玩家名>.json

执行：
  1. 本地备份该 json
  2. 找到目标槽位（inventoryContents 的空位或指定 slot）
  3. 按同文件已有物品格式写 ItemStack：
     {
       "==": "org.bukkit.inventory.ItemStack",
       "DataVersion": 4903,
       "id": "minecraft:enchanted_book",
       "count": 1,
       "components": {
         "minecraft:stored_enchantments": "{\"minecraft:sharpness\":10}",
         "minecraft:custom_name": "\"锋利X\""
       },
       "schema_version": 1
     }
  4. up.mjs 传回，核 md5
  5. 玩家上线核对

注意：
  - components 的值是字符串化 JSON（双重编码）
  - 附魔书用 stored_enchantments，装备用 enchantments
  - 自定义名参考同文件写法（带 extra 的 JSON 文本或普通字符串）
```

### 6c. 从 InvAutoBackup 恢复

`/invbak list` → 找文件 → `/invbak restore <文件名>`（整包替换）。见 [08](08-备份与恢复.md)。

## 7. 废土附魔恢复（专项）

背景：数据包故障期间 `ruined:*` 被剥离。模板参考（其他玩家仍保留）：

- netherite_axe：`corrosive_strikes:2` + `salvager_saw:1`
- netherite_sword：`arc_chain:1`
- trident：`reactor_surge:1`
- mace：`aftershock:2`
- diamond_pickaxe：`corrosive_strikes:2`

```
流程（以 YonmkoQWQ 为例）：
  1. 等玩家离线（或让其重登后保持离线窗口）
  2. getbin plugins/Multiverse-Inventories/worlds/world/<名>.json
  3. 定位目标装备（按 id/自定义名）
  4. components["minecraft:enchantments"] 里加 "ruined:xxx": N
     （注意该值是字符串化 JSON，转义双引号）
  5. up.mjs + md5
  6. 玩家上线，hover 装备验证附魔名与等级
```

脚本参考：`srv/give_book.mjs`（等离线→改 JSON→校验的模式，可复用）。


## 9. 事故响应模板

发现事故（世界坏了/刷屏/起不来）时：

1. **止血**：必要时面板重启进安全配置（移走坏包、禁用肇事插件）。
2. **留证**：latest.log、相关 config、坏包本身都 getbin 到本地 `/tmp/incident-<date>/`。
3. **复盘**：写进 [03-更新日志](03-更新日志.md) 的「事故」小节——时间线、根因、影响面、修复、后续 action。
4. **补课**：把新发现的坑加进 [10-故障排查](10-故障排查与已知问题.md) 或本规程。
