# 08 · 备份与恢复

三层防线：**InvAutoBackup**（玩家物品快照）、**CoreProtect**（方块/容器流水，可回滚）、**世界文件级备份**（面板/手动，最后防线）。

---

## 1. InvAutoBackup（玩家背包快照）

### 机制

| 触发 | 行为 |
|---|---|
| 定时（默认 10 分钟） | 备份所有在线玩家 |
| 玩家退服 | 立即备份该玩家（reason=`quit`） |
| 服务器关闭 | 备份所有在线玩家（reason=`shutdown`） |
| `/invbak now` | 手动全量 |

### 存储

```
plugins/InvAutoBackup/backups/
  <玩家UUID>/
    20261011-143000-timer.yml
    20261011-144512-quit.yml
    …
```

每人保留最近 **288** 份（约 2 天 @ 10min），超出自动删最旧。单份 YAML 包含：

- 背包 36 格（`inventoryContents`）
- 盔甲 4 格 + 副手
- 末影箱 27 格
- 血量/饥饿/饱和/ XP 等级与经验/维度/坐标

### 命令

| 命令 | 权限 | 说明 |
|---|---|---|
| `/invbak now` | `invbak.use`（默认 OP） | 立即备份全部在线玩家 |
| `/invbak list` | `invbak.use` | 列自己的备份（最新 20 条） |
| `/invbak restore <文件名>` | `invbak.restore`（默认 OP） | **整包替换**背包/盔甲/副手/末影箱 |

### 恢复流程

1. 让玩家**退服**（或确认离线）。
2. OP 执行 `/invbak list` 找到目标文件名，或直接翻 `backups/<uuid>/` 目录。
3. `/invbak restore 20261011-143000-timer.yml`。
4. 玩家上线核对。

**注意**：
- restore 是**整包替换**，不是合并。恢复后当前背包内容被覆盖（当前内容仍有一份 `quit` 备份兜底）。
- 与 Multiverse-Inventories 的 JSON 是两套存储。若怀疑 MV JSON 损坏，可从 InvAutoBackup 的 YAML **手动**把物品 JSON 贴回 MV 文件（格式不同，需人工转换组件写法）。
- 这是**应急快照**，不是世界备份。方块改动、建筑、掉落物不在此列。

## 2. CoreProtect（方块/容器流水）

### 能力

- 记录放置/破坏/容器存取/死亡/聊天（视 config）。
- 游戏内查询与回滚：`/co l`、`/co i`（inspect）、`/co rollback <参数>`。

### 存储

- MySQL：`160.202.254.65:33306`，库 `coreprotect`，用户 `minecraft`。
- **IP 白名单**：外部直连 TCP 能握手但 MySQL 协议层被 reset。**只有游戏服自身出站能连**。
- 因此无法本地直连导数据；查询一律走游戏内 OP 命令，或临时写小插件/命令桥（不推荐，侵入大）。

### 常用查询（游戏内）

```
/co l 10m                 # 最近10分钟我周围的方块/容器流水
/co l 1d block            # 最近1天我周围方块改动
/co l u:玩家名 1h container # 某玩家1小时容器操作
/co i                     # 手持 inspect，点方块看历史
```

### 回滚

```
/co rollback r:10 t:1h u:玩家名   # 半径10，时间1小时，某玩家
```

**回滚前**：确认时间窗、半径、玩家，必要时先 lookup 再 rollback；回滚会写新的流水（可再回滚回来，但世界状态已经动了）。

### 保留策略

以 `plugins/CoreProtect/config.yml` 的 `check-updates`/`purge` 相关键为准。数据库体积随时间增长，主机面板可看 MySQL 库大小。

## 3. 世界/文件级备份

### 现状

- **无自动世界备份插件**（Chunky 只预生成，不备份）。
- 依赖 **simpfun 主机面板的备份功能**（如有）——需在面板确认是否开启、频率、保留几份。
- 手动兜底：SFTP 拉 `world/region/`、`world/datapacks/`、`plugins/` 关键配置。

### 建议的最小手动备份集（出大事时拉这些）

```
/world/level.dat
/world/datapacks/*.zip
/world/region/                 # 大；平时别拉，出事按需
/world/level.dat_old
/plugins/Multiverse-Inventories/worlds/
/plugins/Multiverse-Core/worlds.yml
/config.yml
/server.properties
/plugins/*/config.yml          # 逐个
```

### 玩家物品的手动恢复（不用 InvAutoBackup 时）

1. SFTP 拉 `plugins/Multiverse-Inventories/worlds/<世界>/<玩家名>.json`。
2. 本地备份一份。
3. 用编辑器改目标槽位的 ItemStack JSON（DataVersion 4903，组件值多为字符串化 JSON）。
4. 玩家**离线**时 `up.mjs` 传回，核 md5。
5. 玩家上线。

格式参考见 [05-世界与多世界](05-世界与多世界.md)。

## 4. 备份策略总表

| 层 | 工具 | 频率 | 覆盖 | 恢复入口 |
|---|---|---|---|---|
| L1 玩家物品 | InvAutoBackup | 10min + 退服 + 关服 | 背包/盔甲/副手/末影箱/状态 | `/invbak restore` |
| L2 方块/容器 | CoreProtect | 实时（MySQL） | 方块、容器、死亡 | `/co rollback` |
| L3 世界文件 | 面板备份 / 手动 | 待确认 | 全部 | SFTP 覆盖 + 重启 |
| L4 数据包基线 | `/datapack-backup/*-orig-backup.zip` | 静态 | 5 个地形包原版 | 解压覆盖 |

### 已知缺口

- **L3 自动化状态未知**——去面板确认；若无自动备份，至少每周手动拉一次 `world/region` + 全部 `plugins/*/config.yml`。
- InvAutoBackup 只管物品，不管**玩家位置之外的世界状态**（刷怪塔、红石、潜影盒里的物品链）。
- 废土包没有 orig 备份——当前上传版就是唯一基线，**改前先本地留一份**。
